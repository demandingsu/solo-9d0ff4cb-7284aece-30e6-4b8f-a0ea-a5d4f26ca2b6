# 航拍无云画幅合成

把不同时间拍摄、带云掩膜的航拍瓦片合成一张可交付的透明画幅，并导出逐像素来源。
技术栈：FastAPI + Pillow + SQLite，前端为服务端渲染的单页，Docker Compose 可运行。

另附**林地变化监测**入口（`/flights`）：在固定样区（≤256×256 像元）上按拍摄日期登记
多期已对齐画幅与黑白林地掩膜，逐像元比较相邻可见观测，输出采伐/复绿变化 CSV。

## 快速开始

```bash
# Docker Compose（数据保存在 named volume `mosaic-data` 中）
docker compose up --build
# 打开 http://localhost:8000

# 或本地运行
python -m pip install -r requirements.txt
export MOSAIC_DATA_DIR=./data
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

测试：

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

## 页面功能

| 操作 | 说明 |
| --- | --- |
| 设置画幅宽高 | 上限 20000×20000，且总像素 ≤ 1600 万（逐像素 CSV 的规模上限）。 |
| 上传瓦片 | 字段：瓦片号、修订号（正整数）、整数 X/Y、RGB PNG、同尺寸二值云掩膜 PNG。提交后立即重算预览。 |
| 替换瓦片 | 对同一瓦片号提交**更高的修订号**；旧修订保留在清单里但不再参与合成。 |
| 撤回瓦片 | 清单中每个生效修订都有“撤回”按钮；撤回后重算预览，被它覆盖的像素由其余瓦片回填。 |
| 预览 | 棋盘格背景显示透明区域；`/preview.png`、`/preview.csv` 可直接下载。 |
| 发布 | 把当前输入冻结渲染成 `mosaic.png` + `sources.csv` + `manifest.json`，存入版本目录。 |
| 下载 | `/download/latest/...`、`/download/<seq>/...`、`/download/<version_id>/...` 均可；历史版本保留。 |

其它端点：`/versions`（JSON 版本列表）、`/healthz`（健康检查）。

## 林地变化监测（`/flights`）

首页右上角“林地变化监测”进入。面向林地调查员：在多期已对齐的航飞画幅上圈一个
固定样区，找出采伐（林地→非林地）与复绿（非林地→林地）的位置，以及变化发生在
哪两次航飞之间。

| 操作 | 说明 |
| --- | --- |
| 设置固定样区 | 宽、高各 ≤ 256 像元。登记第一期航飞后尺寸即锁定；删除全部登记后才可更改。 |
| 登记航飞 | 字段：拍摄日期（YYYY-MM-DD）、样区尺寸的 RGBA/RGB PNG 画幅、同尺寸纯黑白 PNG 掩膜。画幅透明像元 = 未观测；掩膜白 = 林地、黑 = 非林地（只接受 0/255 两值）。 |
| 替换航飞 | 同一拍摄日期再次登记即替换当日画幅与掩膜。 |
| 删除航飞 | 清单中每期都有“删除”按钮；该日观测被移除后，跨越该日的变化记录会重新连接。 |
| 变化 CSV | `/flights/changes.csv`，列 `x,y,from_date,from_category,to_date,to_category`，类别取值 `forest`/`nonforest`；按像元行序再按日期排序。页面同时给出按日期对汇总的变化像元数。 |

规则：

1. **相邻可见观测对比**：逐像元按拍摄日期排序，只比较前后两次**可见**（非透明）
   观测；中间缺测的日期被跳过，变化记在最近两次可见观测之间（可跨缺测日期）。
2. **观测只提取一次**：登记时把画幅+掩膜解析成逐像元观测存入
   `flight_observations`，之后任何重算都只读这份已提取的观测，不再解码旧图。
3. **增量重算**：补录旧日期、替换同日画幅或删除某期时，只重算该日观测
   **新增、移除或改类**所影响的变化记录——即以该日为端点、或跨越该日的记录；
   其余记录原样保留。页面会提示本次“影响像元 / 变化记录 -删/+增”。
4. **同事务生效**：航飞行、观测、变化记录在一个 SQLite 事务里提交；任一步失败
   整体回滚，航飞清单与变化表都不变，原变化 CSV 照常可下载。

典型流程：用本工具把每期航飞合成并发布，下载 `mosaic.png`（透明 = 无有效观测），
裁到样区尺寸后在 `/flights` 按拍摄日期登记，并附上对应的林地分类掩膜。

## 合成规则

1. **同号取最新修订**：每个瓦片号只让（未被撤回的）最新修订参与合成。
2. **云像素不作来源**：云掩膜中任何非零值都视为有云；有云像素永远不会被当作颜色来源。
3. **重叠像素优先级**：先取无云的来源；多个无云来源之间取**提交时间最新**的瓦片
   （按提交时间戳、再按记录 id，而不是修订号——修订号只在同一瓦片号内比较）。
4. **无来源透明**：所有来源都对该像素有云时，PNG 对应像素 alpha = 0。
5. **来源 CSV**：逐像素一行，列 `x,y,tile_id,revision`；顺序为从上到下、从左到右。
   透明像素的 `tile_id`/`revision` 留空（**空字符串表示“无来源”，绝不会写成某种瓦片名**）。
6. **画幅裁剪**：瓦片可以部分或完全落在画幅外，落在画幅外的部分被裁掉；完全在外的瓦片不参与。

## 发布的一致性保证

* **同一组输入**：发布时先在数据库锁内读出画幅尺寸与生效瓦片列表（含文件、掩膜、
  尺寸、哈希），这份快照交给渲染器；随后在锁外渲染。期间的任何上传/撤回/改画幅只会
  修改数据库，不会改到这份快照，因此 PNG 与 CSV 一定来自同一组输入指纹。
* **不露半成品**：
  * 每个版本先写入 `published/.tmp-<token>/`，三个文件全部写完后用 `os.replace`
    一次性重命名成 `published/<seq>-<id>/`；目录名只在完成时可被查询到。
  * 数据库记录在该目录可见后才插入；若插入失败则删除该目录。
  * 下载时再次校验 SHA-256（与数据库记录一致才返回 200），否则返回 503；且拒绝从
    `.tmp-` 前缀目录读取。`/download/latest` 在发布失败时依旧指向上一完整版本。
  * 预览同理：渲染到 `previews/.tmp-*`，完成后原子改名为内容指纹目录；渲染失败保留
    上一张预览并显示错误，不会把新旧输入混在一起显示。仅当渲染期间草稿未变化，才把
    预览标记为“已是最新”。
* **文件与指纹**：每个版本附带 `manifest.json`，记录输入指纹、画幅、全部瓦片的
  坐标/尺寸/图像与掩膜 SHA-256，以及 PNG/CSV 的 SHA-256。

## 数据模型

* `revisions`：每次上传一行。`(tile_id, revision)` 唯一；`status` 为 `active`/`withdrawn`。
  文件按 `tiles/<tile_id>/r<revision>/<random>.png` 与 `.mask.png` 幂等保存。
* `published_versions`：每个发布版本一行，含指纹、尺寸、统计与两文件的 SHA-256。
* `settings`：画幅尺寸、草稿状态版本号、预览版本、错误信息、草稿统计、样区尺寸。
* `flights`：每期航飞一行，`flight_date` 唯一；记录画幅/掩膜文件（`flights/<date>/`）、
  SHA-256、观测像元数与林地像元数。
* `flight_observations`：逐像元观测，只存可见像元；`category` 1 = 林地、0 = 非林地，
  主键 `(flight_date, x, y)`，另有 `(x, y, flight_date)` 索引供单像元时间序列查询。
* `change_records`：逐像元变化记录，主键 `(x, y, from_date, to_date)`；
  与观测表始终一致（增量维护）。

SQLite 使用 WAL + `synchronous=FULL`，所有读写经由一把进程内锁串行化；应用以单进程
单 worker 运行（见 Dockerfile）。

## 验证

`tests/` 覆盖：

* 验收与边界：瓦片号/修订号/画幅校验，掩膜尺寸与二值格式，RGB 要求，重复修订。
* 合成：云像素透明、云像素永不作为来源、重叠时最新提交优先、全部有云时透明、
  同号只取最新修订、部分出界裁剪、指纹对画幅/掩膜敏感。
* Web 流程：上传 → 预览 → 来源 CSV；更高修订替换旧修订；撤回后从其余瓦片回填；
  新瓦片的云露出旧瓦片无云像素。
* 发布一致性：PNG/CSV 来自同一快照；发布后改稿不影响已发布版本（字节级比较）；
  **渲染进行中并发上传**时发布仍只用快照；**模拟渲染失败**时数据库里不出现新版本，
  `/download/latest` 仍是上一完整版本，恢复后可正常发布；预览渲染失败时不产生版本、
  恢复后可发布。
* 林地变化监测：样区尺寸边界与锁定、日期/尺寸/掩膜二值与模式校验、RGB 画幅全观测；
  基本变化 CSV、**跨缺测日期的变化**、**补录旧日期**、**同日换图只影响当日记录**、
  删除后跨日重连；替换时只解码新上传（间谍函数计数，其余日期沿用已提取观测）；
  **模拟重算失败**时航飞与变化表均不变、原 CSV 可下载、无残留文件，恢复后可登记；
  随机登记/替换/删除后变化表与“由观测全量重算”的参考结果逐步一致。

## 已知限制

* 逐像素 CSV 在千万像素级别会很大（约 10–20 MB+ 每百万像素），因此画幅总量限制在
  1600 万像素；如需更大画幅应改为游程或元数据格式。
* 预览为同步重算：上传/撤回请求会等待渲染结束。大画幅时请求会变慢（简单实现取舍）。
* 仅单进程部署（`uvicorn` 单 worker）时，进程内锁才能保证互斥；多 worker 需要换成
  数据库级锁或单写进程。
* 未实现鉴权/用户隔离；同一实例的草稿对所有访问者共享。
* 未实现瓦片删除（只支持撤回，保留历史）；未实现缩略图、瓦片重投影/重采样，
  位置与尺寸按像素原样放置。
* 变化监测假定各期画幅已对齐到同一样区坐标系，不做配准/重投影；样区变更需先清空
  航飞登记（观测与变化记录随之清空，不保留历史）；变化 CSV 在下载时由变化表即时
  生成（样区 ≤ 256×256 像元，规模有界），不提供历史快照版本。
